# 删除角色（瘦身）完整操作参考

> 本文档记录「只保留 fj200c_main / fj200c_information / admin / mario，删除其他 6 个角色」的完整流程、操作时序与详细步骤，供后续新增/删除角色时参考实现。

## 1. 目标

从 10 个角色的全栈系统（9 用户端 + admin）瘦身为 4 个角色（3 用户端 + admin）：

| 保留角色 | 前端 |
|---|---|
| `admin` | admin |
| `fj200c_information` | fj200c_information |
| `fj200c_main` | fj200c_main |
| `mario` | mario |

被删除的 6 个角色：`fw100`、`fw150`、`ftj1c`、`city3d`、`protocol_generator`、`qgc`。

---

## 2. 前置分析（动手前必读）

角色注册表唯一源在后端 `src/roles.rs`（`ROLE_REGISTRY`），通过 `GET /api/meta/roles` 暴露；前端 key/name/permissions 运行时拉取，**无需**手写副本。但以下信息是前后端/部署三处**手写**的，删除角色时全部要同步：

- 菜单 `MENU_CONFIG`、应用地址 `ROLE_APP_URLS`：`packages/shared/src/roles.ts`
- 权限枚举 `Permission`：后端 `src/common/models.rs` + 前端 re-export（生成）
- 模块声明/路由/静态托管/内嵌：`src/main.rs`、`src/routes.rs`、`src/embedded_assets.rs`
- OpenAPI 聚合与断言：`src/api_docs.rs`（paths/schemas/tags + `export_openapi` 测试的数量断言）
- 种子账号与建表：`src/database.rs`
- 部署脚本与构建脚本：`deploy.bat`、`build-frontends.ps1`、`package.json` workspaces

> 关键原则：**先删后端引用 → 再删前端/部署 → 再生成类型 → 最后编译验证**。顺序不可颠倒，否则编译报错难以定位。

---

## 3. 操作时序（总览）

```text
1. 后端 roles.rs + models.rs 权限
2. 后端 routes.rs / main.rs / embedded_assets.rs / service.rs 引用
3. 后端 api_docs.rs（paths/schemas/tags + 测试断言数）
4. 后端 database.rs（建表 + 种子账号）
5. 删除后端角色模块目录
6. 前端 packages/shared/src/roles.ts（菜单 + URL）
7. 删除前端 frontend/<role> 目录
8. package.json / build-frontends.ps1 / deploy.bat
9. 删除过时 generated/api 目录 + 修 generated/index.ts 桶文件
10. npm run gen:api 重新生成
11. cargo check / cargo check --features embedded / 前端 build
12. 同步 AGENTS.md 与 README.md 文档
```

## 4. 详细步骤

### 4.1 后端：角色注册表与权限枚举（`src/roles.rs`、`src/common/models.rs`）

- `ROLE_REGISTRY`：删除被删角色的 `RoleDef` 项，保留 4 个。
- 模块头 `//!` 的角色表格（注释）同步删到 4 行 —— 注释与实现防漂移。
- `src/common/models.rs` 的 `Permission` 枚举：删除对应变体（如 `Fw100Monitor`、`Ftj1cMonitor`、`Ftj1cHelp`、`City3dView`、`Fw150Monitor`、`ProtocolGeneratorMonitor`、`QgcMonitor`）。
- 顺带修正 `find_role` 等函数 doc 注释里的示例角色名。

### 4.2 后端：引用与路由（`src/routes.rs`、`src/main.rs`、`src/embedded_assets.rs`、`src/common/service.rs`）

- `src/routes.rs`：
  - 模块头 `//!` 的路由树/中间件说明删减。
  - `create_router` 内删除 `let xxx_routes = crate::xxx::routes::xxx_router(db.clone());` 及 `.nest("/api/xxx", xxx_routes)`。
  - 注意：路由表 doc 注释必须用 `///`（外层文档注释），**不要**误写成 `//!`（内层），否则 `cargo check` 报 `E0753 expected outer doc comment`。
- `src/main.rs`：
  - `mod xxx;` 声明删除。
  - dev 模式静态托管 `.nest_service("/xxx", ServeDir...)` 删除。
  - 注释里“嵌入 N 个前端 dist”数量同步改。
- `src/embedded_assets.rs`：`embed_assets!` 与 `embed_app_routes!` 两处宏调用里删除对应 app/struct。
- `src/common/service.rs`：`stop_all_services_except` 里删除 `if keep_role != Some("xxx") { crate::xxx::service::stop_service(); }`。

### 4.3 后端：OpenAPI 聚合与断言（`src/api_docs.rs`）

- `paths(...)`：删除被删角色的所有 `crate::xxx::handlers::...` 项。
- `components(schemas(...))`：删除被删角色的模型/请求体。
- `export_openapi` 测试：
  - 从 `for path in [...]` 列表移除被删路径。
  - 更新两个断言数字：`assert_eq!(paths.len(), X)` 与 `assert_eq!(operations, Y)`。
  - 数量计算方式：
    - 路径数 = 各保留模块唯一路径之和（本次 auth 3 + meta 1 + seed pwd 1 + users 4 + fj200c_information 7 + fj200c_main 13 + mario 2 = 31）。
    - 操作数 = 所有保留 handler 的 HTTP 方法次数之和（本次 37）。
  - **AGENTS.md 与 README.md 中同样数字需同步**。

### 4.4 后端：数据库（`src/database.rs`）

- 删除被删角色的 `seed_passwords` 种子账号条目（`seeds` 数组）。
- 删除被删角色专属建表：本次删掉 city3d 的三张表（`city3d_districts` / `city3d_buildings` / `city3d_events`）及相关索引、以及一整段 city3d 城市数据种子（区域/建筑/事件）。
- 修正章节编号（删后可能产生跳号，重新顺一遍）、模块头种子账号表格、以及“插入 N 个种子账号”的注释。
- 注意：`database.rs` 中 mega 大段（如城市建筑数据）删除时，建议先 `Read` 定位精确边界，再用 `Edit` 整段替换为空，保留 `tx.commit().await?;` 与收尾 `Ok(())`。

### 4.5 后端：删除模块目录

用 `> Remove-Item -Recurse -Force src\fw100, src\fw150, ...`（文件多、含二级目录时比逐个 DeleteFile 高效）。删除前确保上述所有 Rust 引用已清干净，否则 `cargo check` 报找不到模块。

> 可顺带清理仅被删角色使用的公共文件（本次删除了 `src/common/ledger.rs` 及其 `pub mod ledger;` 声明）。若某公共模块仍被保留角色共用，则**保留**，只清理其文档注释里对被删角色的引用。

### 4.6 前端：共享包菜单与地址（`packages/shared/src/roles.ts`）

- `MENU_CONFIG`：删除被删角色的整段 `key: { userMenus, adminMenus }`。
- `ROLE_APP_URLS`：删除被删角色的 `key: { dev, prod }`。
- 同步清理各函数 JSDoc 里对被删角色的示例引用。

### 4.7 前端：删除应用目录与生成文件

- 删除 `frontend/fw100`、`fw150`、`ftj1c`、`city3d`、`protocol_generator`、`qgc` 整目录（含 `dist/`、cesium 等大文件，用 `Remove-Item -Recurse -Force`）。
- 删除 `packages/shared/src/api/generated/api/<tag>/` 中已被删的 tag 目录（orval 不会自动清理旧文件）。

### 4.8 工程与部署脚本

- `package.json`：`workspaces` 数组移除被删前端，保留 `packages/shared`。
- `build-frontends.ps1`：`$apps` 列表精简，并把脚本/日志里的“N 个前端”改掉。
- `deploy.bat`：删除被删角色的 config 生成、`copy /y config-xxx.ini`、以及 URL echo 行；“构建 N 个前端”注释同步。
- 删除根目录被删角色的样例 config（本次删了 `config-ftj1c.ini`、`config-qgc.ini`）。

### 4.9 修复生成的桶文件（关键）

orval tags-split 会生成 `packages/shared/src/api/generated/<tag>/<tag>.ts`，但**不管理** `generated/index.ts` 这个桶文件。删除角色后它会残留对已删 tag 的 `export * from './api/xxx/xxx';`，导致 `vue-tsc` 报 `TS2307 Cannot find module`。

手动编辑 `generated/index.ts`，只保留现存 tag 的导出（admin / auth / fj200c-information / fj200c-main / meta / mario + `./model`）。

### 4.10 重新生成类型

```powershell
npm run gen:api   # = cargo test export_openapi && orval
```

- 重新生成 `openapi/openapi.json`（此时 `export_openapi` 测试断言会验证 31/37 数量）。
- orval 重新生成 `packages/shared/src/api/generated/`。
- 若修改了后端 handler 的 doc 注释（如 logout 的 keep_role 说明），需**再跑一次 gen:api** 才能同步进生成的 TS 注释。

## 7. 常见陷阱（本次踩坑记录）

1. **doc 注释 `//!` vs `///`**：routes.rs 的函数文档里把表行写成 `//!`（内层文档注释）会报 `E0753`。函数文档须用 `///`。
2. **api_docs.rs 的 Edit 大块替换易丢内容**：删 paths 段时把相邻保留模块（fj200c_information / fj200c_main / mario）也误删或重复，务必以 `cargo check` 报错回查。
3. **generated/index.ts 桶文件残留**：orval 不清理它，必须手动删掉已删 tag 的 `export *`。
4. **Cargo.toml 未用依赖**：被删角色专用依赖（socket2 / reqwest / rust_xlsxwriter）删除后可剩为未用，不影响编译，可选清理（本次保留未动，避免引入风险）。
5. **数字注释防漂移**：`api_docs.rs` 断言（31/37）、`AGENTS.md`、`README.md` 三处数字必须一致。
6. **数据库旧库**：`fj200c.db` 若已存在，旧种子账号/表不会自动清除（`database.rs` 只做 INSERT OR IGNORE）。全新部署会自动创建新结构；旧库可手动删库或忽略遗留账号。

## 8. 回滚要点

- 若需恢复某角色：反向执行 —— 从 git 恢复 `src/<role>/` 目录与前端 `frontend/<role>` → `roles.rs`/`models.rs` 加回枚举与 RoleDef → `routes.rs`/`main.rs`/`embedded_assets.rs` 加引用 → `api_docs.rs` 加回 paths/schemas 并更新断言数 → `package.json` workspaces 加回 → 跑 `npm run gen:api` → 编译验证。
- 提交前所有生成文件（`openapi.json`、`generated/`）需重新生成并入库。
